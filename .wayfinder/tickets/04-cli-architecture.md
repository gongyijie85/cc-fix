# Ticket: CLI 工具架构设计

**类型**: `wayfinder:grilling` (HITL)
**状态**: Open / Unclaimed
**阻塞**: 01, 02, 03（需要调研结论）

## Question

基于调研结果，CLI 工具的架构应该如何设计？

需要决策的问题：

1. **项目结构**：
   - monorepo（核心库 + CLI）还是单包？
   - 是否发布为 npm 包供其他工具集成？

2. **CLI 框架选择**：
   - commander.js（轻量）
   - yargs（功能丰富）
   - oclif（Salesforce 出品，适合复杂 CLI）
   - 其他？

3. **检测流程**：
   - 交互式（逐步引导）还是批处理（一次输出所有结果）？
   - 是否需要 JSON 输出模式供其他工具消费？

4. **修复流程**：
   - 自动修复前是否需要确认？
   - 是否需要 `--dry-run` 模式预览修复内容？
   - 修复失败时的回滚策略？

5. **配置管理**：
   - 目标地区/语言如何配置？（命令行参数 / 配置文件 / 交互式选择）
   - 是否需要 profile 功能（保存多套环境配置）？

**输出**：架构方案 + 技术选型决策 + 命令设计草案
