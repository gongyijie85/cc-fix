# 无提权原生文件系统助手（T22 设计变更）

原计划（spec 0.2 初稿）要求实现一个"经用户确认后短时提升、只接受白名单策略写入"的提权浏览器策略助手；落地时发现浏览器策略（HKCU\Software\Policies\…）是当前用户注册表写入，**不需要提权**。本 ADR 记录：白名单助手以**无提权原生文件系统助手**形态落地——用 Rust 原生进程提供 Node 无法原子完成的安全原语（NTFS 重解析点拒绝、同句柄字节比对删除），产品主进程永不提升。

Status: accepted

## 背景

- ADR-0007/0008 定调：桌面壳与本地 GUI 服务是非提升进程，安装器每用户无管理员。
- 浏览器策略六槽（ADR-0011）全部位于 HKCU\Software\Policies\（Chrome/Edge），普通进程可写，无需 UAC。
- 但状态仓储需要两类 Node 难以安全提供的原语：① 删除前拒绝 NTFS 重解析点（防止符号链接/junction 边界逃逸）；② 备份文件"先精确字节比对、再同一句柄删除"的原子删除（消除 check/use 间隙，避免条件竞争）。
- 原 spec 的"提权策略助手 + UAC 取消→降级"路径因此失去存在理由；直接砍掉提权设计可同时消除 UAC 弹窗、提权边界审计面与"助手被滥用"的威胁模型。

## 决策

1. **无提权原生助手**（native-helper/，Rust）：一个请求即退出的进程，仅接受固定形状 JSON 请求，不做任何系统级写入之外的事。
2. **固定作用域**：只处理状态根目录下名为 `persist-backup.json` 及其 `.prev` 的文件；拒绝任何非字面子路径（含 .. 与重解析点）。
3. **原子删除原语**：字节精确比对后才在同一句柄上删除，返回 deleted/missing/mismatch；mismatch 不删除（fail-closed）。
4. **拒绝面**：任意命令/脚本/路径、重放请求、跨会话请求均在写入前被拒绝（Rust 单测语料覆盖）。
5. **主进程永不提升**：桌面壳、Node 服务、CLI 均保持普通权限；不存在需要"UAC cancel → 降级"映射的路径——拒绝即失败，由调用方按策略槽降级处理（ADR-0011 每槽降级）。
6. 若未来出现真正的机器级（HKLM/HKCR）写入需求，须另立 ADR 重新引入提权边界；本 ADR 不排除该可能。

## Considered Options

- **提权策略助手（原计划）**：拒绝。浏览器策略是 HKCU 写入，提权不解决任何实际问题，反而引入 UAC 弹窗、签名/审计与滥用面。
- **纯 Node 实现**：拒绝。Node 无法把"遍历检查"与"后续 open/rename"合并为原子操作（durable-file.ts 注释明言 identity-checked 非原子），重解析点竞争需要原生代码。

## Consequences

- 正面：无 UAC 打扰；提权边界从威胁模型中消失；备份删除获得原生原子保证；助手可独立审计（Cargo 单测 2 个，拒绝语料 + 同句柄比对删除）。
- 约束：产品写入范围被限制在 HKCU/每用户路径（与 ADR-0008 每用户安装一致）；"组织策略管理下的 access_denied"按既有每槽降级路径处理（GUI 已展示原因，如安全软件注册表防护）。
- 验收标准已按本设计改写（tasks/todo.md T22）：UAC 相关条目删除，替换为越界拒绝、字节比对删除与保持非提升的验证。
