# 持久化转换采用耐久事务与收敛式完整恢复

cc-fix 修改的是多个彼此独立的 Windows 权威存储，操作系统不提供跨环境变量、注册表、时区和语言设置的原生事务。产品因此采用应用层耐久事务：保护目标转换只有在目标强度包含的全部必需项完成写入并读回验证后才提交；`persist off` 则以不可覆盖的日常快照为目标持续收敛，所有原值均恢复并验证后才提交日常状态。备份存在、命令返回成功或部分步骤完成都不代表模式已经提交。

## Transaction boundary

一次 `persist on` 事务包含请求的保护强度与地区、对应的环境变量、系统时区、浏览器策略，以及深度保护的 Windows Locale、首选语言列表和 Culture。保护强度、地区和状态元数据作为一个保护目标共同提交。备份、事务日志和锁是事务的耐久基础设施，不是可以独立提交的保护结果。

标准保护与深度保护的必需设置写入失败时，事务保留旧保护目标并逆序补偿所有已修改项；单项补偿失败不能阻止其余补偿。只有全部补偿读回验证成功，才可宣称恢复旧目标。若事务从日常状态开始且补偿完整，本次尚未提交的新备份可以删除；任一补偿不完整则保留备份和事务日志，健康状态进入“需恢复”。

唯一允许提交为“降级”的设置失败，是可明确分类为浏览器策略受组织管理或访问被拒。此时提交请求的保护目标、健康状态记为“降级”，并展示未对齐的策略槽。未知策略错误与其他必需项错误均为致命失败。检测复测或追加式操作日志写入失败不撤销已经验证并提交的系统设置，但必须报告可观测性异常。

## Durable journal and lock

任何系统修改前，事务日志先持久化事务 ID、旧目标、请求目标、步骤计划、每项原值与目标值。单项写入前状态变为 `applying`，写入并从权威存储验证后变为 `verified`；最终状态元数据仅在所有必需项满足提交条件后原子更新。浏览器重启、注销或新进程才会观察到的效果属于“待生效提示”，只要权威存储已对齐就不构成事务失败。

修改操作使用包含随机事务 ID、PID、进程启动时间和心跳的独占锁。活进程持锁时所有新修改请求返回忙；遗留锁只有在确认原进程已不存在后才能接管，不能仅凭文件年龄覆盖。接管后必须先处理关联的未完成事务。只读状态、历史和诊断在事务期间仍可用，但必须标明事务 ID、请求目标、当前阶段和结果尚未提交；事务期间的检测只是瞬时快照，不得更新保护状态或形成修复前后评分。

启动时发现未完成事务，系统进入“需恢复”，禁止开始新的保护转换，只允许查看、诊断和恢复。保护转换的恢复按事务日志补偿回旧目标；`persist off` 的恢复继续向日常快照收敛。

## Complete restore

`persist off` 不在单项失败后停止，也不把已经恢复的项目重新写回保护态。它尝试全部恢复项，记录并验证每项进度，失败后保留不可覆盖的原始备份与事务日志供幂等重试。完整还原必须精确重建原值，包括键原本不存在、值为 `null`、空字符串和空语言列表；全部通过后才清除生效地区、提交日常模式并清理活动事务与原始备份。

## Backup schema and durability

旧备份只允许可证明无损的迁移：完整合法字段直接升级，可由旧字段唯一确定的信息显式转换。缺失的日常原值不得用当前环境补齐，因为当前值可能已处于保护态。无法安全迁移时保留旧文件，生成只读迁移副本并进入“需恢复”，等待用户确认恢复策略。

备份快照不可覆盖。备份、事务日志和状态文件均通过同目录临时文件写入、刷新到磁盘后原子替换，并保存最近一个校验通过的前代副本和内容校验值。读取时优先当前有效版本；当前损坏时才回退前代，同时把健康状态标为异常。

## Testable invariants

1. 在状态元数据提交前，任何查询都返回旧保护目标，并明确存在未提交事务。
2. 任一必需步骤未验证成功时，新保护目标永不提交；明确的受管/拒绝策略例外只可提交为“降级”。
3. `persist on` 致命失败后，补偿覆盖所有已修改项且按逆序尝试；任一补偿未验证即进入“需恢复”。
4. `persist off` 可重复执行，已验证恢复项保持不变，未完成项继续重试；部分恢复永不提交日常模式。
5. 原始值的“不存在”、`null`、空字符串和空列表在备份、迁移与恢复中保持可区分并可验证。
6. 进程在任一步骤前后中止，重启均能由事务日志确定下一步，不会把当前保护态写成日常备份。
7. 活锁不能被并发修改操作夺取；死锁接管后不能跳过未完成事务。
8. 损坏的当前状态文件只能回退到校验通过的前代，并显式报告健康异常。
9. 事务期间的只读检测不能提交状态，也不能参与跨目标的修复前后评分。
10. 浏览器重启或 Windows 注销提示与权威存储验证分离，不会把“待生效”误判为写入失败。

## Consequences

实现需要把当前顺序式 flow 拆分为计划、执行、验证、提交和恢复阶段，并以显式状态仓储取代“备份存在即已开启”的推断。事务文件增加了实现和测试复杂度，但能让断电、进程中止、部分恢复与旧 schema 迁移具有确定、可重试且不污染原始快照的语义。
