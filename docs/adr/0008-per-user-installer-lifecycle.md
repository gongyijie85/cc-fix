# Windows 安装器采用单用户、单活动版本与状态安全卸载

CC-Fix 公开版使用 Inno Setup 6.7.x 生成 Windows 10/11 x64 单 EXE 安装器。每个 Windows 用户只维护一个正式版安装，安装到 `%LOCALAPPDATA%\Programs\CC-Fix`，安装本身不请求管理员权限。稳定 `AppId`、固定安装目录和单一用户 PATH 段共同标识活动版本；所有用户/机器安装和多正式版本并存不属于首发渠道。

安装器只拥有程序文件与系统集成，不能把 `%APPDATA%\cc-fix` 的保护状态当成可随应用删除的缓存。程序卸载与完整还原是两个独立动作：默认卸载路径必须先让系统回到已验证的日常状态；在用户明确选择仅移除程序时，恢复数据必须完整保留，以便后续重装接续。

## Fresh install

安装器包含桌面壳、固定补丁版本的官方 Node.js 24 LTS x64 私有运行时、单文件 ESM 核心 bundle、独立 CLI 启动器、许可证、卸载器和 Microsoft x64 WebView2 Evergreen 离线安装器。安装器检测 WebView2，缺失时离线补齐；不得依赖首次启动联网。

开始菜单入口始终创建。桌面快捷方式默认创建但允许取消；CLI 始终安装，当前用户 PATH 默认加入 `%LOCALAPPDATA%\Programs\CC-Fix\bin` 但允许取消。PATH 操作按规范化路径段进行大小写不敏感去重，安装器只拥有这一段；卸载时精确移除它并保留用户后来增加的所有内容。安装完成后广播环境变更，并提醒已打开的终端可能需要重新启动。

安装器记录用户对桌面快捷方式和 PATH 的选择，供升级与修复复用。开发版和 throwaway 原型必须使用不同标识、目录和快捷方式，不能读取或占用正式版安装注册。

## Process and transaction preflight

安装、升级、修复和卸载前只识别 CC-Fix 桌面壳及其可验证的私有服务，不按通用 `node.exe` 名称结束进程。空闲应用先收到优雅退出请求；存在修改事务、未完成事务或“需恢复”状态时，升级和普通卸载均被阻止，用户必须先返回应用完成或恢复。

不得用重启后的延迟文件替换掩盖被占用文件，也不提供绕过事务保护的强制升级。WebView2 安装若要求重启，程序文件可以完成安装，但安装器不自动启动应用、也绝不自动重启 Windows；交互模式明确提示，静默模式返回标准“成功但需要重启”结果。

## Upgrade, repair and downgrade

更高版本使用稳定 `AppId` 在固定目录原位升级。安装器先校验新载荷并保留可回退的旧受管文件与安装注册，然后替换全部受管文件；不迁移、不覆盖用户状态或诊断数据。数据 schema 迁移由新应用首次启动执行，并遵循 ADR-0006 的耐久、可验证、失败进入“需恢复”规则。

再次运行相同版本提供修复安装：重新校验并覆盖受管程序文件，按已记录选择恢复快捷方式和 PATH，重新检查 WebView2；不改变备份、事务、保护目标、地区偏好和操作历史。

旧版本安装器默认拒绝覆盖新版本。需要回退时，用户先卸载当前受管文件并保留用户数据，再安装旧版；旧版必须先检查数据 schema。不能安全读取时只允许导出诊断或安装回兼容版本，不得用旧代码改写新数据。

安装或升级失败必须恢复升级前完整的受管文件和安装注册，不能留下新旧混合版本；用户数据始终不动。已成功安装的共享 WebView2 可以保留。文件回退自身失败是独立严重结果，日志必须列出未恢复文件并阻止启动混合版本。

## Uninstall and data retention

普通卸载先读取保护模式、健康状态和事务状态。处于标准/深度保护时，默认动作是使用当前安装的核心执行完整还原，读回验证为日常状态后再删除程序；恢复失败则停止卸载并建议修复安装。处于“需恢复”或有未完成事务时同样阻止普通卸载。

用户可在明确风险提示后选择“仅删除程序、保留当前系统设置和全部恢复数据”。该逃生路径删除受管程序文件，但保留原始备份、状态、事务日志、操作历史和偏好，并输出重装恢复说明；绝不同时提供删除恢复数据的选项。

卸载默认保留原始备份、状态、未完成事务、操作历史和地区偏好，默认删除滚动诊断日志和临时文件。只有系统已验证为日常状态且没有未完成事务时，才启用默认不勾选的“删除全部 CC-Fix 用户数据”。删除前解析精确目标，确认仍位于预期根目录，拒绝符号链接、目录联接和其他重解析点；只删除已知数据，不使用宽泛通配符，不删除父目录。

保留状态后重新安装属于“保留状态重装”：首次启动先校验现有备份和 schema，展示检测到的保护目标与健康状态，不能创建或覆盖原始备份。无法安全迁移时进入“需恢复”，不能自动假设日常状态。

## Silent mode and diagnostics

静默安装采用与交互安装相同的默认组件选择。静默卸载默认保留用户数据；发现非日常状态、未完成事务或“需恢复”时返回稳定的非零结果且保持安装不变。只有显式 `RESTORE_AND_UNINSTALL` 才尝试完整还原后卸载；`REMOVE_USER_DATA` 是独立显式参数，并且仍需通过日常状态与无事务检查。

交互失败页提供简明原因、日志位置和重试动作。脱敏安装日志写入 `%LOCALAPPDATA%\CC-Fix\installer-logs` 并滚动保留。发布规格必须为以下语义定义稳定、文档化的进程退出码与机器可读结果标识：成功、成功但需重启、用户取消、事务阻塞、降级被拒、恢复失败、前置组件失败、文件回退失败和不安全数据删除被拒。

## Testable invariants

1. 普通安装、升级与修复不读取或写入用户恢复数据内容。
2. 安装器只维护一个规范化用户 PATH 段，重复安装不重复，卸载不破坏其他段。
3. 活动或未完成修改事务存在时，受管文件不被替换或删除。
4. 升级成功后不存在旧受管文件；升级失败后不存在新旧混合的可启动版本。
5. 旧安装器不能覆盖新版本；旧应用不能改写不兼容的新 schema。
6. 修复安装不改变保护目标、健康状态、原始备份、偏好和操作历史。
7. 非日常状态下任何路径都不能删除恢复数据。
8. 普通卸载只有在完整还原验证成功后才删除程序；逃生卸载必须保留全部恢复数据。
9. 数据删除不跟随任何重解析点，也不能越出精确用户数据根目录。
10. 静默模式对相同前置状态产生稳定退出码，不弹出交互提示，也不自动重启系统。

## Consequences

用户可以像普通 Windows 软件一样安装、覆盖升级、修复和卸载 CC-Fix，同时不会因删除程序失去恢复原始系统设置的能力。代价是安装器必须与应用状态仓储建立只读预检和受控恢复接口，并实现严格的升级回退、PATH 分段维护、数据删除边界及静默退出码测试。
